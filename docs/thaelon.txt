────────────────────────────────────────────────────────────────────────────────
1. WHAT THIS PROJECT IS
────────────────────────────────────────────────────────────────────────────────

Thaelon is the public-facing website / portfolio for a small software engineering
studio. It is a single-page application (SPA) that presents:

  - Who Thaelon is (about, values, founder profile)
  - What they build (2 live products: Clinora, KareerOS)
  - How they work (5-phase process)
  - What they can build for clients (skills, capabilities)
  - How much it costs (pricing pillars + scope tiers)
  - How to contact them

The site is branded as "next-gen" — the design language is glassmorphism +
animated starfield background, very dark by default, premium typography.

Tagline: "Imagine. Engineer. Evolve."

4. APP ARCHITECTURE — HOW IT FITS TOGETHER
────────────────────────────────────────────────────────────────────────────────

App.jsx is the root. It holds:
  - theme state ('dark' | 'light') — persisted to localStorage
  - calls useScrollReveal() once to wire up IntersectionObserver
  - passes theme to <Starfield> and toggleTheme to <Nav>
  - renders in fixed layer order: Starfield → Nav → main sections → Footer

The page render order (DOM top to bottom):
  1. <Starfield>     fixed canvas behind everything, z-index: 0
  2. <Nav>           sticky header, z-index: 50
  3. <main>
       - Hero
       - CodeTicker   (horizontal scrolling dev terms strip, aria-hidden)
       - About
       - Skills
       - Process
       - ProductListing
       - Team
       - Pricing
       - Contact
  4. <Footer>

Sections are NOT lazy-loaded. All mount at once. The scroll reveal hook
applies enter animations as they scroll into viewport.

5. THEME SYSTEM
────────────────────────────────────────────────────────────────────────────────

Two themes: dark (default) and light.

Theme is stored as:
  - React state in App.jsx
  - `data-theme` attribute on <html> (document.documentElement)

All theme-specific CSS is written as:

6. STARFIELD CANVAS — THE ANIMATED BACKGROUND
────────────────────────────────────────────────────────────────────────────────

File: src/components/Starfield.jsx

The most complex component. It renders a full-screen <canvas> fixed behind
all content (position: fixed; inset: 0; z-index: 0).

It has a STATE MACHINE for theme transitions:
  'enter-dark'   → initial dark load animation
  'enter-light'  → initial light load animation
  'dark'         → steady dark
  'light'        → steady light
  'to-light'     → transition animation dark→light
  'to-dark'      → transition animation light→dark

DARK MODE draws:
  - ~400 stars (210 on mobile) with twinkle animations
  - A moon (top-right area) with surface texture dots and a glow halo
  - Shooting stars (random intervals, ~380–820 frames between)
  - UFO (random, occasional, crosses the screen with beam)
  - Spaceships (occasional, less frequent)
  - Background star colors: white, cool blue-white, warm yellow-white, violet-white

LIGHT MODE draws:
  - Sky gradient: deep blue top → lighter horizon
  - Sun (top-right area) with god rays radiating outward
  - Animated clouds (slow drift left, wrap-around)
  - Birds (V-shaped, flap animation, small groups)
  - Horizon warmth gradient: ONLY in the bottom ~18% of canvas
    (was previously bleeding into mid-sections — FIXED by pushing to H*0.82–1.0)

IMPORTANT: The horizon gradient in drawSky() must remain at H*0.82–1.0.
  If you move it higher, the warm peach/sand tone bleeds into sections
  like Process and Products and looks terrible.

Current horizon code:
  const horiz = ctx.createLinearGradient(0, H * 0.82, 0, H)
  horiz.addColorStop(0, 'transparent')
  horiz.addColorStop(0.5, 'rgba(255,210,140,0.07)')
  horiz.addColorStop(1, 'transparent')

Canvas is responsive: resizes on window resize, redraws setup.
Mobile check: window.innerWidth < 768 reduces star count.
Respects prefers-reduced-motion: cancels animation if user has it set.

7. SECTION BACKGROUNDS — GLASSMORPHISM SYSTEM
────────────────────────────────────────────────────────────────────────────────

CRITICAL DESIGN DECISION: All sections have nearly transparent backgrounds
so the animated Starfield canvas shows through every section on the page.

Section base backgrounds:
  Dark:  background: var(--dot-grid), rgba(7, 7, 14, 0.18)
  Light: background: var(--dot-grid), rgba(238, 243, 255, 0.18)

The dot-grid is a CSS variable set in :root that creates a subtle dot
texture pattern using radial-gradient.

Some sections (#about, #process, #team, #contact) use slightly more opaque:
  Dark:  rgba(11, 12, 26, 0.22)

Section-specific glow overlays are added via background-image (not background
shorthand) to stack on top of the transparent background:
  Example: #about has a purple glow at 88% right to give depth.

The footer has stronger opacity (0.82) since it's the end of the page and
a solid boundary makes sense visually.

CARDS use glassmorphism — they blur the animated canvas behind them:

  Dark mode cards:
    background: rgba(14-15, 15-16, 28-35, 0.76-0.82)
    backdrop-filter: blur(20-28px)

  Light mode cards (sky-tinted, not white):
    background: rgba(232, 238, 255, 0.66-0.72)
    backdrop-filter: blur(18-28px)
    NOTE: rgba(255,255,255,...) was intentionally changed to rgba(232,238,255,...)
    so light mode cards feel sky-tinted (matches the Starfield sky) not plain white.

If you ever see white/opaque cards in light mode — check that they use
rgba(232, 238, 255, ...) not rgba(255, 255, 255, ...) for the background.

8. SCROLL REVEAL SYSTEM
────────────────────────────────────────────────────────────────────────────────

File: src/hooks/useScrollReveal.js

Any element with className="reveal" will animate in when scrolled into view.
The hook uses IntersectionObserver (threshold: 0.08, rootMargin: 0 0 -40px 0).

When the element intersects, 'revealed' class is added. CSS handles the animation:
  .reveal         → opacity: 0, transform: translateY(24px)
  .revealed       → opacity: 1, transform: translateY(0), transition: ...

Staggered reveals use CSS custom property:
  style={{ '--reveal-delay': '0.1s' }}
  .reveal { transition-delay: var(--reveal-delay, 0s); }

IMPORTANT: Respects prefers-reduced-motion — if the user has that OS setting,
the hook returns early and nothing animates (elements stay visible).

The hook is called once in App.jsx. It runs a querySelectorAll('.reveal') on
mount, so all reveal elements must be in the DOM at that point. Since nothing
is lazy-loaded, this works fine.

13. CSS ARCHITECTURE — KEY RULES
────────────────────────────────────────────────────────────────────────────────

SINGLE FILE: Everything is in src/index.css. ~5300+ lines. Sections are separated
by ASCII comment headers: /* ===== SECTION NAME ===== */

RULE: Never use shorthand `background` when you need to LAYER dot-grid + color:
  Correct:   background: var(--dot-grid), rgba(7,7,14,0.18);
  Wrong:     background: rgba(7,7,14,0.18);  ← wipes out dot-grid

RULE: Section backgrounds must remain nearly transparent (opacity ~0.18–0.22)
so the Starfield canvas shows through. Increasing opacity kills the visual effect.

RULE: Cards must use sky-tinted glass in light mode:
  rgba(232, 238, 255, ...) — NOT rgba(255, 255, 255, ...)
  Plain white looks disconnected from the sky background.

RULE: backdrop-filter: blur() requires a semi-transparent background to be
visible. Cards with `background: transparent` will NOT show blur.

RESPONSIVE BREAKPOINTS:
  < 900px:   tablet adjustments (footer columns, some section layouts)
  < 768px:   mobile (mobile star count in Starfield, nav hamburger appears)
  < 680px:   Team founder card stacks to column
  < 600px:   Various section adjustments
  < 560px:   Modal goes full-width with reduced padding (28px 22px)
  < 480px:   Hero adjustments, team modal band margin adjusts

DOT GRID pattern (--dot-grid variable):
  A radial-gradient dot texture used as a CSS variable, applied to section
  backgrounds to add visual texture that shows the canvas through.

CAPABILITIES SEPARATOR:
  .capabilities has a top separator with a centered accent gradient line
  (a small 80px wide line that acts as a visual section break).

17. KNOWN DECISIONS & GOTCHAS
────────────────────────────────────────────────────────────────────────────────

1. NO TYPESCRIPT — intentional. Pure JavaScript + JSX throughout.

2. SINGLE CSS FILE — index.css is ~5300+ lines. There are no CSS modules.
   All class names use BEM-like naming: component__element--modifier.

3. LOGO APPEARS IN BOTH NAV AND FOOTER — this is correct and intentional.
   Same image file (Thaelon-removebg.png), different class names and sizes.

4. STARFIELD CANVAS HORIZON FIX — The horizon warmth gradient in drawSky()
   was causing warm peach tones to bleed into mid-page sections.
   FIX: pushed gradient to H*0.82 → H (only bottom 18% of page height).
   DO NOT move this gradient higher without testing all sections in light mode.

5. FOOTER LOGO STRETCHING FIX — Footer brand is a flex column. Without
   align-self: flex-start on the img, flex stretches it horizontally.
   footer__logo-img MUST have align-self: flex-start.

6. TEAM MODAL CLOSE BUTTON Z-INDEX — The team modal uses a full-bleed gradient
   band (negative margins to escape modal padding). The modal close button MUST
   have z-index: 10 or it disappears behind the band.

7. TEAM MODAL AVATAR RING SHADOW — The double-ring glow shadow uses specific
   hex colors that match the modal background:
   Dark: 0 0 0 4px #0d0e21  (matches dark modal gradient start)
   Light: 0 0 0 4px #f6f7ff  (matches light modal gradient)
   If modal background changes, update these hex values too.

8. LIGHT MODE CARDS — Must use rgba(232, 238, 255, ...) not rgba(255, 255, 255, ...).
   The sky-tint connects the cards to the light-mode Starfield sky background.

9. GIT RULE — Never commit, push, stage, or run ANY git commands unless the
   owner (Kishor) explicitly asks. This is a hard rule.
